# REVIEW.md

This document summarizes the defects identified in the starter `app/main.py`, how they can be observed, and how they were addressed in my implementation.

| # | Where (function / line) | What is wrong in the starter | How you'd notice it (test, input, or symptom) | How it was fixed in my version |
|---|---|---|---|---|
| 1 | `compute_late_minutes()` | Constructs the shift-start time incorrectly, which can produce inaccurate lateness calculations, particularly around midnight and overnight shifts. | Test a punch near midnight for an overnight shift and compare the result with the intended shift date. | Convert the punch timestamp to IST and construct the shift-start instant using the attendance date and employee shift. |
| 2 | `compute_late_minutes()` | Does not correctly apply the required whole-minute calculation and 10-minute grace period relative to the intended shift start. | For a 09:30 shift, test arrivals at 09:40:59 and 09:41:00. | Calculate whole elapsed minutes against the correct shift start and count lateness only when it exceeds 10 minutes. |
| 3 | `compute_work_hours()` | Uses Python's `round()`, which uses ties-to-even rounding instead of the required half-up rounding. | Test a duration whose calculated hours are exactly halfway between two hundredths. | Use `Decimal` with `ROUND_HALF_UP` and round to two decimal places. |
| 4 | `compute_overtime()` | Constructs the shift-end time on the attendance date even when the shift crosses midnight. | Punch out after midnight for a shift that ends after midnight. | Detect overnight shifts and move the shift-end date to the following day when required. |
| 5 | `compute_overtime()` | Counts overtime without enforcing the required minimum threshold of 30 minutes. | Test punch-outs 29 minutes and 30 minutes after shift end. | Return zero below 30 minutes and count whole overtime minutes when the threshold is reached. |
| 6 | `/health` - `health()` | Reports success without checking whether MongoDB is reachable. | Disconnect MongoDB and call `/health`; the starter may still report success. | Check MongoDB connectivity and return HTTP 503 when the database check fails. |
| 7 | `create_employee()` | A check-then-insert duplicate check can allow concurrent requests to attempt creating the same employee. | Send simultaneous requests with the same `emp_code`. | Add a unique index on `employees.emp_code` and translate `DuplicateKeyError` into HTTP 409 Conflict. |
| 8 | `create_employee()` | Stores `created_at` using a naive local datetime rather than a consistently defined UTC timestamp. | Create an employee and inspect the stored timestamp and its timezone interpretation. | Store the timestamp in UTC and serialize it according to the API's timestamp contract. |
| 9 | `create_employee()` / `EmployeeIn` | Does not adequately validate shift-time and joining-date formats against the contract. | Submit malformed shift times or an impossible `joined_on` date. | Validate shift times and calendar dates before accepting the employee record. |
| 10 | `list_employees()` | Calculates the pagination offset incorrectly by using `page * page_size`, which skips the first page of records. | Request page 1 with page size 20 and inspect the first returned records. | Calculate the offset using `(page - 1) * page_size`. |
| 11 | `list_employees()` | Counts all employees instead of counting the filtered query, causing an incorrect `total` when a department filter is supplied. | Compare the returned `total` with the number of employees matching a department filter. | Use `count_documents()` with the same filter as the list query. |
| 12 | `list_employees()` | Does not enforce pagination bounds or use a stable sort, which can produce invalid requests or inconsistent page results. | Try page 0, page size 101, or request successive pages. | Validate page and page size and sort by `emp_code` ascending. |
| 13 | `punch_in()` | Does not handle an unknown employee before accessing employee shift fields. | Punch in using an unknown `emp_code`. | Return HTTP 404 when the employee does not exist. |
| 14 | `punch_in()` | Uses an inconsistent timezone/date interpretation and does not reliably truncate timestamps to whole seconds. | Test timestamps near IST midnight or timestamps containing fractional seconds. | Normalize timestamps to UTC, truncate to whole seconds, derive the attendance date in IST, and handle overnight shifts. |
| 15 | `PunchInIn` / `punch_in()` | Does not adequately validate the status, timestamp type, or timestamp range. | Send an unsupported status, a floating-point or string timestamp, or an out-of-range timestamp. | Restrict status to allowed values and validate timestamps as integer epoch milliseconds within the accepted range. |
| 16 | `punch_in()` | A check followed by insertion is vulnerable to simultaneous duplicate punch-ins, and the response must not expose unintended database-generated fields. | Send simultaneous punch-ins for the same employee and date and inspect the response fields. | Add a unique `(emp_code, date)` index, translate duplicate-key errors to HTTP 409, and omit MongoDB's `_id` from the response. |
| 17 | `list_attendance()` | Fetching and sorting matching documents in Python does not scale well, and returning database-generated identifiers can violate the response contract. | Inspect the response fields and test listing against a large collection. | Filter, sort, skip, and limit in MongoDB; return the required response fields and convert timestamps to epoch milliseconds. |
| 18 | `list_attendance()` | Does not adequately enforce pagination bounds or define a stable order for records with the same date. | Try page 0 and page size 101, or create multiple records for one date. | Validate pagination and sort by date descending, then `emp_code` ascending. |
| 19 | `list_attendance()` | Does not adequately validate date filters or reject a `date_from` later than `date_to`. | Submit malformed dates or a reversed date range. | Validate date formats and reject reversed date ranges with HTTP 422. |
| 20 | Remaining contract endpoints | The starter leaves required functionality such as punch-out, attendance regularization, monthly analytics, department summaries, the late leaderboard, department trends, and explain endpoints unimplemented or incomplete. | Call the required routes using the supplied OpenAPI contract and check for missing routes or incomplete behavior. | Implement the required endpoints, including punch-out calculations, audit history, analytics aggregations, and execution-stat explain output. |
